# ADR-002：不新开项目，在现有项目上演进

- 日期：2026-10-11
- 状态：已采纳

## 背景

立项之本确立（"AI 负责写，人负责懂"）后，旧实现显得"不纯洁"：6 条找坑规则的 DNA、Java-only 的 analyzer、README 的旧定位。提出是否新开一个干净的项目。

## 决策

不新开 repo。在现有项目上"立新碑"：`docs/vision.md` + README 定位更新，v0.6 起按新使命迭代。

## 理由

- 地基可复用：Engine/Surface 分层、版本化协议、MCP 9 工具、relevance gate、双循环审查、证据回源、unknown 诚实机制、离线架构——这些恰恰是"讲懂"使命最需要的脚手架，v0.1–v0.4 几个月才搭起来。
- "不纯洁"处均为可改项：规则是加法（留作"风险视角"）、Java-only 是一次重构（v0.6 M1）、README 是一句话。
- 时间成本：单人 + AI 团队，新开项目 v0.6 可能两个月追不上现有完成度。
- 新文档范式（版本冻结 PRD + milestones）本就为便宜 pivot 而设计；真 pivot 不了那天再分叉，git 让分叉很便宜。

## 后果

- v0.6 起按"讲懂"使命迭代（M1 引擎抽象 → M2 链路摘要 → M3 学习闭环）。
- 旧 6 条规则降为"风险视角"，不再是主角。
